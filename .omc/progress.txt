Public hook contract (matches plan §2):
  useMiniMap({ width = 80, gap = 2 }) returns:
    pages: MiniMapPageLayout[]                      // proportional layout
    totalHeight: number
    viewport: { top: number, height: number }       // multi-page span aware
    scrollOffsetForMinimapY: (y) => offset
    minimapYForScrollOffset: (offset) => y

Architecture decisions held to:
  ✅ NO scrollOffset field added to PDFState — read virtualizer.scrollOffset
     locally via requestAnimationFrame inside the hook
  ✅ Per-page exact interpolation in BOTH forward and inverse mappings
     (no globally linear ratio anywhere)
  ✅ Safe empty state when virtualizer is null — no rAF, no DOM access
  ✅ Multi-page viewport span via forwardMap(top) − forwardMap(bottom)
  ✅ Skip-frame: setState only fires when scrollOffset OR clientHeight changes

Documented deviations from plan:
  1. Linear scan over pages[] instead of binary search in forward/inverse
     mappings. Same O(N) virtualizer calls as binary search would need;
     reads cleaner. Within plan ("binary-search ... or compute on the fly").
  2. Track virtualizer.scrollElement.clientHeight alongside scrollOffset in
     the same rAF tick — needed for criterion 5 (multi-page viewport.height
     accuracy on resize). Same skip-frame guard, no extra rAF loop.
