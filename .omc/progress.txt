v3 (post-second codex/gpt-5.5 review) addressed 3 finer findings:
  Round-2 finding 2-NEW (asymmetric gap): forward(r.bodyEnd) returned m_{i+1}.top
    in <Pages gap=0> + <MiniMap gap=6> config, breaking round-trip identity at
    the body-end boundary. Fix: explicit boundary clamp `if (offset === r.bodyEnd
    && r.realGap === 0) return m.bodyEnd` before falling through to next page.
  Round-2 finding 5 (NaN sentinel): rAF skip-frame guard would degrade to
    per-frame setState if virtualizer.scrollOffset was ever NaN
    (NaN !== NaN forever). Fix: Number.isFinite() normalization in tick()
    for both scrollOffset and clientHeight.
  Round-2 finding 6 (skip-frame test): asserted viewport.top stayed at 0,
    which React's primitive bail-out would mask. Strengthened with a Probe
    component + render counter — assertion is now "≤1 additional render
    across 5 stable-offset frames", which a buggy implementation cannot pass.

v1 → v2 codex/gpt-5.5 review found 4 real bugs (architect+critic missed them):
  1. forwardMap/inverseMap ignored the virtualizer's gap (default 10px in
     <Pages>). scrollOffset in a real gap mapped to NEGATIVE fraction in the
     next page → backward jump in the minimap
  2. Minimap gap regions broke the "true inverse" PRD criterion — the 10
     fixed sample points happened to skip the gap intervals
  3. Zero-width pages skipped `cursor += gap`, deviating from plan formula
     `top_i = sum(...) + i*gap`
  4. realStartOf silently returned 0 when getOffsetForIndex returned null —
     fabricating page starts during init

Fix applied via strict TDD (RED → verify-fail → GREEN → verify-pass):
  • Added 4 failing tests, one per bug, each explicitly verified to fail
    for the right reason before any production code was written
  • Refactored useMiniMap.tsx with slot-aware mapping: each page has body
    + trailing-gap sub-slots; body↔body and gap↔gap mappings are linear
    within their sub-slot. forward∘inverse is now identity everywhere
  • realStartOf now returns null on unresolved offsets; realPageInfo
    propagates null up; mappings return safe 0 instead of fabricating
  • Cursor advances by (pageHeight + gap) for every page including
    zero-width — matches the plan formula

Public hook contract (matches plan §2):
  useMiniMap({ width = 80, gap = 2 }) returns:
    pages: MiniMapPageLayout[]                      // proportional layout
    totalHeight: number
    viewport: { top: number, height: number }       // multi-page span aware
    scrollOffsetForMinimapY: (y) => offset
    minimapYForScrollOffset: (offset) => y

Architecture decisions held to:
  ✅ NO scrollOffset field added to PDFState — read virtualizer.scrollOffset
     locally via requestAnimationFrame inside the hook
  ✅ Per-page exact interpolation in BOTH forward and inverse mappings
     (no globally linear ratio anywhere)
  ✅ Safe empty state when virtualizer is null — no rAF, no DOM access
  ✅ Multi-page viewport span via forwardMap(top) − forwardMap(bottom)
  ✅ Skip-frame: setState only fires when scrollOffset OR clientHeight changes

Documented deviations from plan:
  1. Linear scan over pages[] instead of binary search in forward/inverse
     mappings. Same O(N) virtualizer calls as binary search would need;
     reads cleaner. Within plan ("binary-search ... or compute on the fly").
  2. Track virtualizer.scrollElement.clientHeight alongside scrollOffset in
     the same rAF tick — needed for criterion 5 (multi-page viewport.height
     accuracy on resize). Same skip-frame guard, no extra rAF loop.
